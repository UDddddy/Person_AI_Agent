## 二、核心知识地图（按主题）

### 主题 1：流式输出 —— SSE vs WebSocket

- **SSE（Server-Sent Events）**：服务端**单向**推送，HTTP 长连接，天然适配 LLM 逐 token 流式。
- **WebSocket**：**双向全双工**，客户端可随时回发消息。
- **为什么 LLM 流式选 SSE**：LLM 输出是从服务端到客户端**单向**的，不需要回传通道；用 WebSocket 是"杀鸡用牛刀"。
- **实现**：FastAPI `StreamingResponse` + `text/event-stream`；LangChain `ChatOpenAI` + `stream_mode="messages"`，`msg_chunk.content` 是文本增量、`tool_call_chunks` 是工具参数增量。

### 主题 2：LangGraph 编排（阶段 3 核心）

- **三要素**：
  - **State**：`TypedDict` + `Annotated[list, add_messages]`（reducer 归约器，多节点追加时自动合并、按 id 去重）
  - **Node**：普通 Python 函数，`输入 state → 返回要更新的字段`（局部更新，未返回字段不变）
  - **Edge**：普通边（固定走向）+ 条件边（按 state 内容动态路由）
- **条件边**：`should_continue` 检查最后一条消息是否带 `tool_calls` → 有则回 tools、无则 END。
- **Checkpoint（SqliteSaver）**：按 `thread_id` 持久化整图状态；重启不丢、不同 session 隔离。
  - 坑：`SqliteSaver.from_conn_string()` 返回**上下文管理器**，必须 `with ... as cp:` 进入。
- **interrupt（HITL 人工审批）**：
  - interrupt 只能在**图节点内部**调用；`invoke` 遇中断**不抛异常**，返回带 `__interrupt__` 键的结果；
  - 恢复用 `Command(resume=决策)` + **同一 thread_id**，节点从头重跑，interrupt 第二次返回 resume 值；
  - 两段式驱动：`while "__interrupt__" in result:` → 取 payload → 人类决策 → `Command(resume=...)` 恢复；
  - **外部驱动只喂决策，不越权 return**——拒绝也要恢复图，由节点生成"被拒"ToolMessage 让 LLM 看到。
- **图结构与节点实现解耦**：基础版 / HITL / SSE 三图拓扑完全相同，差异只在节点内部 → 这正是"LangGraph 作承载底盘"的原因。
- **图可视化**：`graph.get_graph().draw_mermaid_png()` / `print_ascii()`（需 grandalf）。

### 主题 3：工具调用（Function Calling）

- **本质**：LLM 不执行函数，只返回**调用意图 JSON**（`tool_calls`），真正执行的是我们的代码。
- **tool_calls 结构**：`list[dict]`，每项 `{name, args(dict), id, type}`；用 list 是因为一次可能调多个工具。
- **配对**：AIMessage 的工具调用与 ToolMessage 靠 `tool_call_id` 一一对应。
- **动态 vs 写死**：真实场景工具的 schema 由注册表生成、参数由 LLM 生成（动态），不是写死在节点里。
- **原子工具 vs 场景化工具**：场景化（calculator/time）每需求加一个工具 → 数量爆炸；原子工具（read/write/edit/run）4 个覆盖全部文件/命令操作，Agent 自主组合 → 工具数量固定。

### 主题 4：工具管道 + 钩子 + 事件总线（阶段 4-5）

- **ToolPipeline 三阶段**：
  - **Prepare**：查工具 → 校验必填参数（`arg in args` 查键存在，不是值真假）→ before_hook
  - **Execute**：`tool.execute(args)`（BaseTool 异常兜底）
  - **Finalize**：记审计日志（参数/结果/耗时）+ after_hook
- **钩子（Hook）**：流程固定时机点上的"插槽"。
  - `before_hook(name, args) -> str | None`：返回 None 放行；返回字符串=拦截原因，提前 return（后续不执行）
  - `after_hook(name, args, result)`：执行后观察，不改流程
- **横切关注点**（审批/日志/校验）挂管道不塞工具——解耦"做什么"与"怎么做"。
- **EventBus（阶段 5 起点）**：发布-订阅（pub/sub）模型，`emit(event_type, data)` 广播 + `subscribe(event_type, handler)` 监听，通过事件类型解耦。
  - **事件 vs 钩子**：钩子调用点写死（before/after 两处）；事件可任意时机、任意模块、一事件多监听者。

### 主题 5：架构理念（pi / codex）

- **Pi Agent**：事件流驱动一切（可观测性地基）+ 树形会话（append-only JSONL + parentId，可 Fork/回滚/时间旅行）+ 切割点压缩（**工具结果不可切**）+ 4 原子工具 + 25+ Hooks 分层 + 70+ provider。
- **Codex**：三级审批链（Hook → Guardian → User）+ 三层 token 防线（全窗口硬上限/压缩阈值/剩余量提醒）+ 两级压缩（模型摘要 / token 预算换窗）+ 上下文片段注入。

### 主题 6：工程实践坑（都是踩过的）

| 坑 | 原因 / 正确做法 |
|---|---|
| `No module named 'tools'/'app'` | `sys.path[0]`：`python 脚本.py` = 脚本所在目录；`python -m 包.模块` = 工作目录。包内导入必须从根目录用 `-m` 跑 |
| 中文乱码 | Windows 下 `open()` 默认编码不可靠，读写一律显式 `encoding="utf-8"` |
| `PydanticUserError: field overridden` | pydantic v2：子类覆盖基类带注解字段，覆盖也必须带类型注解（`name: str = ...`） |
| `partially initialized module` | 循环导入（registry → run_command → registry）；工具类只依赖基类，注册交给注册表（单向依赖） |
| pytest 收集报 ConnectError | `test/` 下联调脚本顶层有副作用 → 加 `if __name__ == "__main__":` 守卫 |
| 耗时记录变成累计时间 | `start_time` 放类属性（模块导入时求值一次）→ 应放方法内局部变量，每次调用各自计时 |
| git push `Could not connect` | 系统代理开关变化 git 不感知；诊断顺序：先测直连、再测代理端口，手动 `--unset` / 配置 proxy |
