## 今日关键结论

1. **SSE vs WebSocket**：SSE 服务端单向推送，天然适配 LLM 逐 token 流式；WebSocket 双向全双工，LLM 场景输出单向即可，不需要回传通道。实现用 FastAPI `StreamingResponse` + `text/event-stream`。
2. **LangGraph 三要素**：State（TypedDict + `add_messages` reducer，多节点追加靠 reducer 合并）、Node（普通函数，返回要更新的字段）、Edge（条件边按"最后一条消息是否有 tool_calls"路由）。
3. **tool_calls 结构**：是 `list[dict]`（`name/args/id/type`）；AIMessage 的工具调用与 ToolMessage 靠 `tool_call_id` 一一配对；模型输出被截断（`stopReason=length`）时参数可能残缺，应作废重发。
4. **死循环教训**：`agent_node` 必须"看状态"——上一条是 ToolMessage 就作答、否则调工具；否则无条件返回 tool_calls + 无条件回环会触发 `recursion_limit`。
5. **sys.path 机制**：`python 脚本.py` 的模块搜索起点=脚本所在目录；`python -m 包.模块` / uvicorn 的搜索起点=当前工作目录。包内绝对导入（`from tools.xx`）必须从根目录运行，否则 `No module named 'tools'/'app'`。
6. **OpenAI SDK 层级**：`client.chat.completions.create()` = REST 资源导航（client 配置 → chat 领域 → completions 资源 → create() 动作），对应 `POST /v1/chat/completions`。
7. **SSE 流式实现要点**：裸 openai client 无法配合 `stream_mode="messages"`，需 LangChain ChatOpenAI + callbacks；`msg_chunk.content` 是文本增量、`tool_call_chunks` 是工具参数增量。
8. **codex 架构**：三级审批链（Hook→Guardian→User）+ 三层 token 防线（全窗口硬上限/压缩阈值/剩余量提醒）+ 两级压缩（模型摘要 / token 预算直接换窗）+ 上下文片段注入。
9. **pi 架构**：事件流驱动一切（可观测性地基）+ 树形会话（append-only JSONL，可 fork/回溯）+ 切割点压缩（工具结果不可切、保留用户消息、文件操作追踪）+ 70+ provider。
