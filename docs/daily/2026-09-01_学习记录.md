## 今日关键结论

1. **llamaIndex 与 LangGraph 的"生态重叠"**：两者都是全栈 LLM 应用框架，不是单一用途库。都覆盖 RAG 全链路 + Agent 工具调用 + 工作流编排；主攻方向不同（llamaIndex 数据/RAG 见长，LangGraph 编排/Agent 见长），但功能面大面积交叉。计划修正逻辑：LangGraph 生态自带 RAG 组件，RAG 用轻量 Chroma 自组装即可，不必引入第二个平行生态。
2. **双框架学习方案**：不逐功能双写（两套 API 易混淆），而是 LangGraph 负责 Agent 编排（阶段 3）、llamaIndex 负责 RAG（阶段 4），每阶段末用另一框架写最小对照 demo + 对比笔记。目标先定"都了解"。
3. **Function Calling 本质**：LLM 不会执行函数，只返回"调用意图" JSON（tool_calls），真正执行的是我们自己。
4. **AST 白名单安全**：对 LLM 生成/用户输入，用 `ast` 白名单而不是 `eval`（防代码注入）。
